# 注文明細スナップショット（ファイル保存）の設定

注文確定時に送ったメール本文を **サーバーのディスクにファイル** で保存し、発送完了メール送信時に「注文番号＋注文者メール」で照合して本文に含めます。**microCMS は使いません。**

---

## かんたんに言うと

1. 本番サーバーで **書き込み可能なディレクトリ** を 1 つ用意する（例: `./data/order_snapshots`）。
2. 環境変数 **ORDER_SNAPSHOTS_DIR** にそのパスを設定する。
3. それだけ。注文確定時に自動で保存され、発送完了メール送信時に自動で参照される。

---

## 1. 保存先ディレクトリ

- **中身**: 注文ごとに 1 ファイル（JSON）。ファイル名は注文番号とメールから決まる。
- **場所**: 次のどちらか。
  - **ORDER_SNAPSHOTS_DIR を設定する**: そのパスを保存先に使う。例: `/var/app/data/order_snapshots`
  - **未設定**: プロジェクト直下の `.data/order_snapshots` を使う（`process.cwd()` からの相対パス）。

## 2. 環境変数

`.env` または `.env.local` に追加（任意）:

```env
# 注文スナップショットの保存先。未設定の場合は .data/order_snapshots を使用
ORDER_SNAPSHOTS_DIR=./data/order_snapshots
```

- 本番で別ディレクトリを使う場合の例:  
  `ORDER_SNAPSHOTS_DIR=/var/app/data/order_snapshots`
- **未設定でもよい**。その場合はカレントディレクトリの `.data/order_snapshots` に保存を試みる。

## 3. 動作の流れ

1. **注文確定時**（`/api/checkout/complete`）  
   お客様へ送った「ご注文の確認」メールの HTML 本文を、  
   注文番号とメールアドレスに対応する 1 ファイルとして保存する。  
   ディレクトリが書き込み不可（例: Vercel）の場合は保存せず、ログだけ出す。

2. **発送完了メール送信時**（`/admin/send-shipping`）  
   入力された「注文番号」と「送信先メールアドレス」で、対応するファイルを探して読む。  
   見つかったら、その内容を「お届けしたご注文内容」として発送完了メールに埋め込む。  
   見つからなければ、注文番号・追跡番号のみの本文で送信する。

## 4. 注意（Vercel で動かす場合）

- **Vercel のサーバーは再起動ごとにクリアされるため、ローカルディスクへの保存は永続しません。**
- Vercel にデプロイしている場合は、このファイル保存方式では **注文スナップショットは残りません**。  
  発送完了メールは送れるが、「お届けしたご注文内容」は付かない。
- 永続させたい場合は、**Vercel Blob** や **DB（Supabase など）** を使う拡張が必要。  
  Docker や自前サーバーで永続ディスクがある場合は、**ORDER_SNAPSHOTS_DIR** をそのパスにすればそのまま利用できる。

## 5. 既存の注文について

- この機能を入れる **前** に確定した注文は、ファイルが存在しないため、発送完了メールに注文明細は出ません。
